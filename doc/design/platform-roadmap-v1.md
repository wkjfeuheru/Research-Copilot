# 综合投研平台实施分期与验收 v1

日期：2026-11-12。状态：实施路线设计；本次已完成需求收敛和设计文档整理，不代表下列工程阶段已经完成。

配套：[决策入口](README.md) · [产品设计](platform-product-v1.md) · [架构设计](platform-architecture-v1.md)

## 1. 分期原则

按依赖顺序构建可运行的业务闭环：先落实用户、任务和产物，再完成独立数据分析、基本面研究、因子回测。已有报告、数据工具、计算脚本、沙盒和审核能力作为复用基础。

每个阶段既有交付物，也有可检查的退出条件。阶段通过只说明该阶段目标达成，不能推导整个平台已可用。排期、人力、预算和容量暂不填入假定数值；运行与上线前必须形成实际配置及验证记录。

本计划不添加定时/事件触发、团队共享、多人共同编辑、实盘交易或首期完整 Notebook/机器学习范围。

## 2. 阶段总览

| 阶段 | 主要交付 | 依赖 | 关键退出证据 |
| --- | --- | --- | --- |
| P0 合同与实施准备 | 领域/执行合同、现状清单、数据能力矩阵、运行政策字段、旧成果归属方案 | 已确认设计 | 目标可拆为实现工作；数据与恢复等关键假设有证据或明确限制 |
| P1 平台执行基础 | 用户隔离、项目/任务/Run、产物版本、持久队列、独立 worker、最小工作台 | P0 | 两用户隔离、重复提交、后台执行、恢复、版本登记的集成证据 |
| P2 独立数据分析 | 工具服务/文件导入、数据快照、采集与分析角色、检查与导出 | P1 | 不创建报告即可完成第一个业务闭环 |
| P3 基本面研究成稿 | 模型假设、财务计算、Writer/Reviewer 接入、主对话协调、跨项目复用 | P2 | 第二个业务闭环；正文依据、修改重跑与复用可追溯 |
| P4 因子与日频回测 | 因子合同、实验比较、回测执行、Backtester、五类职责按需协作 | P2、P3 中的通用协调/复用能力 | 第三个业务闭环；计算正确性与数据限制均可核验 |
| P5 整体验收与迁移交付 | 全链路验证、运维与恢复说明、历史只读接入、部署/回退方案 | P1–P4 | 三闭环和横向要求的分层证据；真实数据/模型验证按实际范围签收 |

P4 的数据能力调研和计算样例可以在 P0 起准备；正式集成须使用平台共同的权限、执行和产物合同。分期不是创建多套彼此独立的原型。

## 3. P0：合同与实施准备

### 交付

- 核对架构设计引用的当前源码，记录已变更部分；当前六域、16 工具只是此次快照，不写死为平台上限。
- 细化 TaskRevision、ExperimentRevision、Run、Dispatch、ArtifactVersion、ReviewAssessment 和 DatasetManifest。
- 明确每个模块的接口、错误分类、所有权、幂等与事务职责，冻结第一个可实施接口版本。
- 数据能力矩阵：行情/公司行动、财务时点、历史股票池、行业分类、资料文本、导入文件；每项记录合同、实际覆盖、缺口和探索适用性。
- 设计旧 actor 到新用户的映射、旧成果只读访问和新工作流版本策略。
- 定义运行政策的必填字段，保留费用与额度数值待实际执行前确定。

### 退出条件

三个代表性任务均能对应到输入、产物、角色、计算方法和检查合同。数据不足时的结果等级明确；未知来源能力不会被当成已经具备。恢复与重跑、目标修订与代码修复、任务完成与质量通过具有一致语义。

## 4. P1：平台执行基础

### 交付

- 真正的用户身份与后端所有权校验，覆盖项目、任务、文件、产物、事件、记忆和执行控制。
- 项目主对话与任务详情的最小界面；具体任务指向可见，参数修订可追踪。
- 新工作流命名空间、任务/Run 状态、持久队列、独立 worker 入口和预算关联。
- 产物内容存储、版本登记、精确引用、检查记录和候选/正式版本区分。
- 暂停、继续、取消、未知执行恢复和幂等发布。

### 退出条件

1. 两个用户的直接 ID 访问、列表、文件、推送和恢复操作互相隔离；伪造 owner 被服务端拒绝。
2. 重复提交同一操作不创建重复 Run；重复回执不重复发布产物。
3. 关闭浏览器后已提交任务仍可执行，重新打开后可恢复观察。
4. 对明确未开始的队列项安全接续；未知外部执行进入恢复状态，不能盲目重放。
5. 暂停恢复保留 Run 身份与消耗；修改冻结参数产生新修订及执行记录。
6. 使用确定性夹具验证最小任务与产物路径，不把夹具运行计为真实模型验收。
7. 用子执行夹具验证暂停/取消沿研究执行树传播：停止新准入，等待在途收尾；未知后代阻止父级假报停止，恢复不重跑已完成候选。计算尝试身份在外部执行前已持久化。

账户接入方式、具体并发与存储参数在本阶段落实并记录；这是实施配置，不改变已确认的用户隔离要求。

## 5. P2：独立数据整理与分析

### 交付

- FinanceKB 工具适配和可扩展数据接口；文件导入、解析预览、字段映射与错误提示。
- 标准化数据快照、单位/期间/时点说明、来源与转换记录。
- Searcher、Analysist 的独立调用路径，以及任务所需的最小协调和检查能力。
- 统计与图表结果、数据下载、代码查看和导出。
- `completed + exploratory` 的显示、引用、导出与限制继承。

### 退出条件

完成“导入表格或采集数据 → 清洗合并 → 分析图表 → 检查 → 下载”的独立闭环，全程无须创建 report 或调用 Writer。

至少验证：字段歧义、重复/缺失、单位差异、损坏文件、来源不可用、来源合同变化、跨用户资产访问和可复用旧数据。只依赖用户文件或已登记数据的任务，不因无关外部来源不可用而被全局阻断。

PDF 能力按实际解析器范围验收；对扫描件/复杂表格未覆盖部分给出限制，不能把上传成功等同于内容解析正确。

## 6. P3：基本面研究成稿与资产复用

### 交付

- 财务数据与事实、预测、假设分离；指标、估值、情景/敏感性模型的执行合同。
- Writer/Reviewer 消费版本化数据与模型；报告只是可选交付类型，短备忘录也可交付。
- 项目主对话协调多任务，任务上下文独立，输入引用固定版本。
- 同用户跨项目资产发现与复用；方法经验带所有权、来源、适用条件和停用机制。
- 修改参数、生成新版本、比较结果以及限制继承的完整交互。

### 退出条件

完成“基本面研究 → 计算与情景 → 报告 → 检查与有界返工”闭环。核心数字能够追溯到事实或假设及计算回执；引用探索产物时限制不会被写作抹去。

至少验证：在另一项目引用已有数据、源数据新版本不静默替换、旧结论过时提示、目标变更澄清、项目主对话不污染并行任务、非必要人工批准不阻断自主执行。审核通过即可结束例行任务，无强制人工签署。

## 7. P4：因子研究与标准日频回测

### 交付

- 因子定义、计算、面板、检验与验证窗口；标准日频组合回测的配置与计算适配器。
- Backtester 角色，持仓/交易/成本/净值等产物与检查合同。
- 实验配置修订、独立执行、候选比较和完整尝试记录。
- 数据可得性、股票池历史、公司行动/复权、交易条件与成本的能力矩阵及限制传播。
- 对因子/回测的独立调用、与采集/分析/撰写/审核的按需组合。

### 退出条件

1. 可核算小样本验证信号时点、持仓和现金、交易与成本、净值与指标之间的一致性。
2. 代表性数据量下明确内存、时间、并发和文件规模配置，数据不通过模型上下文整批传递。
3. 多候选与参数重跑各自留痕，能比较数据/代码/参数差异；验证窗口与探索窗口清楚区分。
4. 缺少完整历史数据时仍可交付注明限制的探索结果；输入不可计算或核心计算错误时不能以免责声明放行。
5. 达到停止条件后停止探索；返工和子执行不绕过预算。
6. “因子结果独立交付”“已有数据直接回测”“回测后按需生成研究备忘录”均成立。

数据供应商和覆盖程度在本阶段明确。若只能验证受限探索，应签收为受限能力，不能对外宣称已完成完整历史时点回测验收。

## 8. P5：整体验收与历史迁移

### 交付

- 三个代表性闭环、五类业务职责的独立调用和复杂任务协作证据。
- 全链路用户隔离、恢复、预算、质量状态与资产复用验证。
- 集中部署与单人本机模式的部署说明、运行参数、日志与故障处置手册。
- 显式备份、旧成果归属映射、只读接入、回退与完整性核查方案。
- 真实数据与模型的范围、任务、成本、结果、局限和失败原因记录。

### 退出条件

文档中的每个验收案例都有具体执行环境和产物证据。旧成果按正确用户可读，旧 checkpoint 和回执未被重解释；新旧写入路径分开。未知归属或执行状态不通过默认用户或自动恢复掩盖。

实际部署、迁移或付费验收属于后续具体执行工作；本次设计确认不启动这些动作。是否可以宣称生产可用，应以实际目标环境与真实场景验收为依据。

## 9. 验收矩阵

| 编号 | 案例 | 主要验收证据 |
| --- | --- | --- |
| A01 | 独立数据整理与分析 | 数据集、转换记录、图表、检查、导出；无报告依赖 |
| A02 | 基本面研究成稿 | 事实/假设、计算回执、正文引用、检查与返工记录 |
| A03 | 因子到策略回测 | 数据画像、因子定义、配置、持仓交易、绩效、检查与候选记录 |
| A04 | 用户隔离 | 第二用户对文件、搜索、事件、经验、恢复等路径的反向用例 |
| A05 | 跨项目复用 | 同用户来源版本可见、相容性检查、用户间拒绝、限制继承 |
| A06 | 实验重跑与比较 | 新旧输入/代码/参数/环境与输出的差异，不覆盖原版本 |
| A07 | 暂停恢复与幂等 | 浏览器断连、worker 中断、重复命令、迟到结果、执行前登记、父子执行共同收尾与未知外部状态 |
| A08 | 自主执行边界 | 正常步骤自动推进；目标变更澄清；额度与无进展停止 |
| A09 | 探索性交付 | 完成状态与质量分离，限制出现在结果、图表引用和导出 |
| A10 | 独立角色与审核 | 五类职责可独立使用；审核绑定精确版本，不强制全流程或人工签署 |
| A11 | 历史只读 | 旧成果、原归属与原状态可读；不迁移执行 checkpoint |
| A12 | 范围约束 | 未配置定时/公告/行情触发新研究；系统内部恢复不新增未授权研究目标 |

验收关注研究正确性、可追溯性和流程能力，不要求某个因子或策略必须盈利。负结果同样可以是有效研究交付。

## 10. 验证层次与证据格式

| 层次 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 确定性单元/合同测试 | 计算、状态、输入输出、权限规则的指定行为 | 真实模型任务完成能力 |
| 录制响应或脚本模型回放 | 固定数据与行为下的协作、检查和失败路径 | 当前源站覆盖、供应商稳定性 |
| PostgreSQL/Docker 集成 | 事务、持久队列、租约、执行环境与恢复 | 研究结论有效性 |
| 浏览器验证 | 用户流程、状态展示、对话定位、比较和下载 | 后端所有路径的授权和模型质量 |
| 真实数据验证 | 指定来源、证券、期间和时点的实际可得性与语义 | 真实模型编排与完整交付 |
| 真实模型业务验收 | 在声明条件下的实际自主完成、成本与问题 | 未覆盖市场、数据、容量或任务的普遍成功 |

每条验收记录建议包含：代码与配置版本、任务原文、数据来源/时点、模型与环境、运行政策、用户/项目/任务/Run 标识、产物哈希、检查结果、实测用量、失败与限制、原始证据路径。跳过项单列，不计为通过。

真实模型或外部付费服务仅在相应执行任务已获授权且额度确定后运行；授权存在时在其范围内推进，不重复增加例行确认。设计文档不自动提高现有运行额度，也不授权恢复其他任务中的历史付费运行。
