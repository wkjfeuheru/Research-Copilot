## 复测新增的剩余问题与改进方案

以下尚未实施，不混入上面的通过项。本次没有扩大预算或以额外执行绕过阻断。

### P1 分析提交失败的修复路径丢失已完成计算的回执

实际链条是：`e523fc552ba759aab19b32057c984a09` 已完成计算并登记 60 个指标 → 最终结构化回复连续被截断 → 编排建议缩小输出后重派 → `ee0a4194931d57ae8136b182ca40085a` 取得事实，但 `registered_metrics` 为空 → 尝试重算时触发同一工作组原执行次数上限 → 工作流阻断。

`subagents/source_context.py:221` 只从当前 dispatch 的指标字典提供回执；`subagents/services.py` 的 repair 分支继承证据和来源调用记录，没有继承计算回执。`subagents/analysist.py:173` 同样只接受当前 dispatch 指标；后续还要求 execution.dispatch_id 等于当前 dispatch。仅把旧 ID 写入提示词并不足以修复，提交校验仍会拒绝。

最小离线复现 `output/catl-chain-fix-20261112/test_analysis_repair_gap.py` 直接加载本次控制状态，证明相同 work_group 的授权修复任务无法看到前序已登记的两个毛利率指标：**1 failed**。这份刻意失败的诊断测试保留在输出目录，未计入 952 项通过。

建议新增“仅修复提交”的明确路径：绑定原成功 execution ID、原代码/产物哈希、证据范围和修复身份；向修复角色暴露可复用的不可变回执；提交校验沿这条授权关系验证，继续禁止无关任务/跨范围借用。禁止重新执行，也不重置执行或模型账本。若必须改计算，则进入明确的重新计算流程，不能冒充提交修复。

### P1 输出长度耗尽被转成重算建议

已登记的指标远多于派单必需指标，最终回复仍尝试长篇结构化结果，单次输出上限包括 reasoning tokens。既有 `retry_truncated_analysis` 允许一次收尾，但未成功。`orchestration/middleware.py` 的错误提示一律建议重派更少字段，不能区分“计算已完成，仅提交失败”与“计算未完成”。

建议以已登记回执判断下一步：存在完整计算回执时生成精简候选（只含必需指标、结论和局限），必要时通过已有候选文件提交接口分块持久化，再返回短回执；不要复制所有中间指标和原始表格。增加真实 `finish_reason=length` 且已注册 execution 的图回放测试，断言零额外沙盒执行也可进入 Writer。

### P1 存在不能接受的归因口径与精度结果

成功登记不等于分析方法正确。现有沙盒结果把 2026H1 对 2025H1 的结构效应 `-0.08` 从 2026Q3 对 Q2 的毛利率差 `-2.46` 中相减，得到所谓残差 `-2.38`；两个比较区间不同，这不能构成季度变化的归因。`is_estimate=true` 也不能修复不可比口径。分业务数据本身又未明确累计/单季口径，不能仅凭期末日期认定可用于半年度定量拆分。

同时，脚本先把两期毛利率四舍五入为 20.69% 和 23.15%，再求差 -2.46；原值全精度求差为 -2.46525896795012 pp，最终显示两位应为 -2.47 pp。中间舍入导致终值偏差。分业务 source.currency=null 被事实标为 CNY，虽有警告说明，仍不能当成源已披露币种。

建议将“同一比较期间、业务分母和范围”纳入归因输入/派单契约；不满足时只提交已核算的总变化及不可识别项，敏感性情景单列，禁止从实际降幅中扣减异期情景值。计算保留全精度，仅展示时使用 display_precision；用本次原值建立独立重算验收。未知币种及口径保持未知，额外假设与原始事实分开登记。Reviewer 必须覆盖跨期残差、币种假设、舍入链及“未检索≠不存在”。

本轮分析未正式提交，Writer 和 Reviewer 没有运行，因此这些问题尚未形成正式报告。下一次验收应在上述回执复用及方法校验修复后进行，不能把本次已登记指标直接包装成合格报告。
