# 第一阶段：搭建可启动的项目骨架

日期：2026-10-22

## 目标与技术选择

建立可独立运行、验证和继续扩展的前后端工程。本批完成工程基础，随后复现原项目基线，再逐步接入升级能力。

- 后端：Python 3.13、FastAPI、Pydantic、LangGraph，使用 uv 管理依赖。
- 前端：已选定的 React + TypeScript + Vite，使用 pnpm。
- 持久化目标：PostgreSQL + pgvector，本批提供部署配置，业务表和迁移后续实现。
- 保留现有规格文档、原型和 `.venv`；不修改 `settings.json`。

## 工程结构与实现内容

参考[原项目](https://github.com/LUOCHENGQING/my-projects/tree/main/fin-research-multi-agent)的 Agent、工具、模型调用和编排职责，采用可安装的 Python 包结构：

```text
Research-Copilot/
├── src/research_copilot/
│   ├── __init__.py
│   ├── config.py
│   ├── api/                 # 应用入口、路由、响应模型
│   ├── agents/              # 后续各研究 Agent
│   ├── llm/                 # 后续模型客户端
│   └── tools/               # 后续数据和文件工具
├── frontend/
│   └── src/
│       ├── app/
│       ├── pages/
│       ├── components/
│       └── styles/
├── tests/
├── deploy/                 # 容器构建与反向代理配置
├── doc/                    # 保留规格与原型
├── pyproject.toml
├── uv.lock
├── compose.yaml
├── .env.example
├── .gitignore
└── README.md
```

- **仓库隔离**：计划编写时 Git 根目录指向 `F:/`，实施时在项目内初始化独立仓库，使用 `codex/bootstrap` 分支，避免操作父仓库。
- **后端入口**：提供应用工厂、环境配置和 `GET /api/health`。健康响应只说明服务进程可用，不宣称数据库、模型或研究链路已就绪；未配置模型密钥也能启动骨架。
- **模块边界**：Agent、LLM、工具目录只建立包与职责说明。实际开发编排时再加入 `state.py`、`orchestrator.py` 和节点契约，避免提前堆积空实现。旧 RAG、native fallback、隐式 mock 不迁入正式链路。
- **前端入口**：沿用 B 风格，根路由展示对话式研究工作区，包含研究问题输入、技能选择与附件选择；另设记忆、技能空状态页面。没有资料库入口。未接通的发送和上传明确提示，附件选择仅本地展示，不生成虚构任务或报告。
- **运行配置**：开发使用前端 `5173`、后端 `8000`，通过 `/api` 代理联通。Compose 提供前端、后端与 PostgreSQL 服务，生产入口同源代理；数据库采用命名卷，不接触已有数据库。此阶段不部署脚本执行沙箱。
- **依赖与说明**：提交前后端锁文件，容器版本固定；提供环境变量示例、启动命令、验证命令和当前未接入能力说明，不写入凭证。

## 验收标准

- 从项目环境启动后端，健康接口返回明确且符合响应模型的数据。
- 后端配置与健康接口测试通过，无外部模型、搜索或 MCP 调用。
- 前端类型检查和生产构建通过。
- 浏览器验证根路由、导航、对话输入、技能与附件区域，以及记忆和技能空状态；页面不存在资料库入口。
- Compose 配置校验通过；容器启动结果与配置校验结果分开报告。
- README 可指导重新安装与启动；文档、原型和已有环境均得到保留。

本批完成仅代表工程骨架可运行，不代表原项目复现或研究业务验收完成。

## 后续开发顺序

1. **原项目基线**：在隔离目录中固定参考版本，运行其示例与测试，记录真实结果及 mock、降级行为。
2. **研究主链路**：实现各 Agent 输入输出契约、LangGraph 路由、任务接口与人工暂停恢复；用离线夹具验证流程。
3. **真实数据与交付**：接入 CNEquity MCP、并行网页搜索、附件处理、分析图表和引用校验。
4. **技能与持久化**：实现按需加载、可信脚本沙箱、PostgreSQL checkpoint、研报知识记忆。
5. **任务经验总结**：会话终态后异步总结成功与失败经验，支持幂等写入、失败重试和记忆管理，且不阻塞简报交付。

每阶段先明确范围和验收条件，再实施；真实外部调用单独核验，不以离线测试代替。
