## 已实现

- 分析新增 `submit_analysis` 精简提交接口；正式分析保存后由宿主构造结果，不再要求模型重复整份最终 JSON。截断修复只携带任务、指标回执与简短提交要求，已完成计算时不再暴露计算工具。编排错误反馈区分尚未计算和已计算未提交。
- 授权修复派单保存原执行、指标/图表内容的哈希绑定。指标副本保留原 execution ID 和源派单；提交及审核按授权关系验证工作组、范围、内容、原始证据和产物哈希。修复派单为仅提交模式，业务服务与沙盒入口禁止重算，不增加执行余额。
- 固定程序和宿主复核保留 Decimal 全精度链条；`value` 是展示值，宿主 `calculated_value` 保存独立复算的计算值，后续公式使用后者。分析提交和 Reviewer 预检查重新从依赖原值计算，不信任回执中的计算缓存。
- 归因指标增加结构化 comparison，核对当前/基期、期间口径、实体、报表范围、收入分母及 actual/scenario。不同期间、分母、范围或情景混算被拒绝；实际归因所需口径未知时保留缺口。来源显式 currency=null 不得登记为 CNY，必须保持 unknown。
- 更新毛利率方法、执行合同和主控说明：优先计算有据可依的总变化；不能要求缺少输入的贡献或跨期残差，不能将无法量化解释为零贡献。

代码保护可识别的公式和声明的比较关系，不宣称对任意自定义财务模型进行了形式证明。数据本身的可信度与经济因果解释仍由独立审核核查。

## 剩余问题与下一步方案（尚未实现）

1. **失败候选稿缺少可恢复的正式身份，修复会重新生成全文。** 真实证据是原最终候选稿在修复后只读回放通过，但新派单又生成缺引用的版本。应将每次结构化候选稿及其分析引用、模板哈希、内容哈希、校验错误原子保存；恢复任务只投影授权前序候选稿，并做局部修改、重新校验。旧分析或旧模板不一致时必须拒绝复用，仍须走正式发布与 Reviewer。
2. **报告正文和引用清单由模型重复维护，容易遗漏。** 当前 `SectionClaim` 允许空 `fact_refs`，数字直到完整正文校验才被拒绝。应增加结构化数字片段：明确选择 metric ID 或冻结 fact key，由宿主渲染已登记值、单位和精确引用，禁止从数值相等自动猜测引用。继续保留整文数值审计、符号/期间校验和未绑定数字拒绝。
3. **派单要求与模板约束仍可能冲突。** Supervisor 的恢复任务曾另列“后续跟踪”，Writer 随后增加第五节。应由宿主把固定标题、章节数量、字数预算和必需事实/结论清单作为统一合同注入派单与 Writer schema；逐节校验后组装最终版本。验收用例必须覆盖缺 fact_refs、标题数字、遗漏 C2、五节误生成、单节超长、错误季度和过期候选稿。

这些是新的 Writer 可靠性缺口，未以放宽校验、手写报告、增加模型预算或新增执行次数掩盖。后续应先用本轮真实候选稿做无模型回归，再验证原问题的一次完整新会话；本次不标记产品整链路验收通过。
