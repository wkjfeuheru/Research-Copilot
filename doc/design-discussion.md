# 复现与升级设计讨论

## 已确认方向

- 先形成参考项目的运行基线，再升级。
- 已确认以 LangGraph 为编排基础；此前决定不引入 DeepAgents。新增长期记忆需求后，用户提出是否需要 DeepAgents 的疑问，待核实能力边界再决定，尚未授权变更框架。
- Skills 支持按需加载的指令、模板和可选脚本。
- 升级后的主场景：输入研究问题，产出投研简报。
- 扩展目标包括图表、报告、研报 PDF、调研笔记及中间产物的文件管理。
- 首版覆盖 A 股市场的个股与行业问题。
- 资料来源结合系统公开检索与用户上传。
- 简报采用核心结论、依据与分析、风险与不确定性、来源四部分结构。
- Skills 支持用户显式触发与系统自动发现。
- 原始资料可跨任务复用；笔记、图表、简报等产物按研究任务分别保存。
- 正常流程自动推进；资料不足或 Risk Checker 判定需要人工判断时暂停，可自动修正的问题先走修订分支。不设置默认的研究计划审批。
- 人工可以补资料、调整范围或终止任务；人工确认不将证据缺口变成已验证事实。
- 用户显式指定技能后，系统仍可按需补充其他技能；技能不能绕过风险检查与审核规则。
- 首版仅执行项目维护的可信技能脚本，原始资料只读，脚本只写当前任务产物目录。
- 沿用原项目 Markdown 简报形式，增加正文嵌入的可视化图表，并单独保存图表文件。
- 升级版提供 Web 界面，支持提问、上传资料、进度查看、人工介入和简报阅读。
- 支持人工暂停及服务重启后恢复原任务；补资料后重做受影响的分析与风险检查。
- 首版支持可提取文字的 PDF，并保留页码定位；扫描件不纳入首版，提取失败需报告缺口。
- 用户提供 MCP 服务作为主要数据入口，网页搜索作为补充。
- Retriever 替换为 Data Fetcher，替换原项目 RAG 链路；基线阶段仍先复现原项目。
- 上传文件采用文件工具链：保留 PDF 原件、提取带页码文本，支持列表、关键词查找和按页或范围读取，首版不建立文档向量检索库。
- Data Fetcher 根据研究计划自主选择工具、分步获取数据与补充搜索，受调用次数和时间预算约束；负责资料整理和缺口标记，分析计算由 Analyst 负责。
- 用户指定 CNEquity（https://github.com/rootSunc/CNEquity）作为计划接入的 MCP 服务，尚未完成服务运行验证。
- 提炼研报核心观点或摘要，作为 Agent 跨任务长期记忆，扩展原先仅复用原始资料的范围。
- Data Fetcher 提炼摘要后，检查来源、页码及摘要与原文的一致性，通过后进入跨任务召回；同一文档版本去重，不同机构的矛盾观点并存，保留日期与出处。用户可停用错误记忆，后续任务不再召回；不将整份简报自动存为长期事实。
- CNEquity 由用户独立部署和维护，本项目连接已有 MCP 服务，不承担数据湖初始化与日更。
- 已接受：基线不增加向量检索；升级版采用 PostgreSQL + pgvector，仅对研报摘要和观点做语义召回，结合结构化过滤及原件回读。
- 已接受 Docker 沙箱执行：首版仅运行项目维护的可信脚本，默认断网、按次隔离，暂不开放模型生成代码执行。
- 执行器接收脚本标识、结构化参数及输入文件标识；Agent 不直接控制 Docker 命令或挂载。输入只读，仅输出和临时目录可写，固定镜像依赖，限制权限与资源。
- 执行结果通过校验后登记正式产物；失败保留日志，不将半成品视为有效结果。执行记录应关联脚本/镜像版本、输入哈希、参数及产物。
- 首版单用户，不建设团队权限体系。
- Writer 后增加交付检查，检查引用、图表和结论一致性；文字问题返回 Writer，分析问题返回 Analyst 并重新经过 Risk Checker。
- 首批验收场景为个股财务分析和行业三家公司对比；具体标的和日期根据 CNEquity 的实际数据覆盖确定。
- 调用失败或预算耗尽时显式暂停或失败，不自动切换 mock，不静默重跑整个流程；保留已完成资料和产物，用户可以重试、补充资料、缩小范围或终止。该规则适用于升级版；基线阶段如实记录原项目降级行为。
- 调用次数、执行时间和修订轮数设置可配置上限，默认值纳入实施方案评审。
- Web 布局：左侧任务列表及新建入口，中间研究问题、阶段进度、人工介入和图文简报，右侧本次资料、引用与产物；独立管理页覆盖长期记忆和 Skills（独立资料库已按最新需求移除）。视觉样式在原型阶段确认。
- 研究模型、Embedding 与网页搜索独立配置；研究模型与 Embedding 暂记为待定，不阻塞设计，真实接入验收前确定。
- 网页搜索并行调用 DeepSeek 与 Tavily 搜索 API，汇总后过滤内容。单路失败时显式记录失败来源，证据充分可继续；关键证据不足则升级人工，两路均失败则暂停。这是通用失败暂停规则的明确例外。
- 用户要求搜索内容过滤规则放在提示词层，由 Agent 判断并输出标准结构化结果；每个 Agent 定义标准输入/输出 JSON Schema，参考原项目设计。升级版具体契约尚待设计，不将此要求直接视为原项目已完整实现的事实。
- 内容判断与程序校验区分：提示词指导去重、相关性、来源、时效和分歧处理；JSON Schema 用于约束结构，来源/文件引用等客观约束的校验设计纳入方案评审。Schema 校验不能证明内容正确。
- Windows 开发、Linux 部署；采用 Docker Compose 管理应用与 PostgreSQL，计算脚本经独立执行器进入受限容器，CNEquity 独立维护。

## 最新需求调整

- 移除独立资料库页面与导航，保留研究对话中的附件上传及任务内证据读取。
- 一次任务会话结束后，在后台总结成功经验、失败教训及适用边界，写入长期记忆；与原有研报知识分开管理。
- 原型已增加结束会话、后台状态、失败重试和任务经验查看；全部为内存演示，真实后台总结尚未实现。具体触发、幂等、准入与预算设计见规格草案。

## 能力核实与待决建议

- LangGraph checkpointer 用于任务状态恢复，Store 支持跨任务数据与可选语义检索；长期研究记忆并不要求引入 DeepAgents。官方文档：https://docs.langchain.com/oss/python/langgraph/add-memory
- DeepAgents 可将长期记忆作为文件访问，StoreBackend 可基于 LangGraph Store；记忆准入、来源追溯、时效和冲突处理仍需应用设计。官方文档：https://docs.langchain.com/oss/python/deepagents/memory
- 已接受将研报记忆保存为带来源的摘要和观点记录，不直接视为系统认可的事实。
- CNEquity 默认以只读 MCP 查询本地数据湖，需初始化及持续更新，由用户维护。当前仅核查公开文档与源码，未运行服务或验证真实数据覆盖。来源：https://github.com/rootSunc/CNEquity
- 官方长期记忆生产示例提供 PostgresStore/AsyncPostgresStore，位于 langgraph-checkpoint-postgres 包；与同包内用于运行状态恢复的 PostgresSaver 是不同接口。用户已接受 PostgreSQL + pgvector 的升级方向；具体业务表结构仍为设计建议。
